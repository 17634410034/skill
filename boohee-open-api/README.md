# 薄荷健康食物数据库

一个给 AI 助手用的查数据技能：在对话中查**食物营养**、识别吃了什么、生成个性化食谱、记录体重与饮食。

官方接口文档：`https://ai.boohee.com/docs/` ｜ 控制台（拿 API Key）：`https://ai.boohee.com/console/`

技能里的参数表、字段说明、枚举取值，全部是官方文档的**逐字快照**，不是二手总结，也不是模型凭记忆写的。助手每次按「先确认 API Key → 再选接口请求 → 最后合并总结」三步走，回答里的数据来自实时接口。

## 它能帮你做什么

1. **查食物营养** — 按名称或条码查热量与几十种营养素、GI/GL、红绿灯等级、食材构成、单位估重；详情默认拉满可选字段，返回完整营养项、扩展单位与菜肴食材，而不是只给四项基础营养。多样食物一次算出整餐合计；按营养素做排行。
2. **识别吃了什么** — 拍饭菜照识别食物与重量，或说一句「早上喝了一杯牛奶两个鸡蛋」按餐别拆分。
3. **生成食谱** — 给性别、体重、目标热量，叠加口味、菜系、忌口、慢病与饮食模式（控糖、16:8、高蛋白、素食、地中海、DASH 等），出一整周分餐食谱，支持「换一换」。
4. **记体重与饮食** — 写入、修改、删除、按天查询，返回当日按餐次分组的热量与三大营养素。

结果会整理成**结论 + 中文表格/卡片**：热量、蛋白质等带单位，红绿灯、餐别等枚举翻成中文，完整营养与食材构成分节展示；不会把接口 JSON 或原始返回直接甩给你。

## 怎么开始

在支持 `SKILL.md` 技能规范的 Agent 平台安装本技能后即可使用。安装路径因平台而异（`~/.qoder/skills/…`、`~/.workbuddy/skills/…`、项目内 `.qoder/skills/…` 等），文中命令一律用绝对路径，不要把 `<技能目录>` 照抄成相对路径。

查询与记录需要一个 API Key，配一次就长期复用：

1. 打开控制台 `https://ai.boohee.com/console/` → 登录或注册开放平台账号 → 左侧「API Key 管理」→ 创建 API Key，复制 `sk-` 开头的完整密钥。
2. 在对话里说「记住我的 key 是 sk-xxx」，助手会写入本机 `config.json`（默认在技能目录，技能目录只读时在 `~/.boohee-open-api/`）；也可以自己打开该文件，填最上面带 ★ 的 `api_key` 那一行。
3. 之后直接说「查一下牛奶按 250ml 算的营养」。

没有 key 时，助手会先告诉你怎么获取，并停下来等你，不会用示例数据或模型常识代替真实查询。本技能只做查询与记录，**不生成接入代码、不展示接口返回示例**。

体重、身高、忌口、饮食目标同样说一次即可，助手会记进同一个文件的 `profile` 区块，后续不再反复问。

## 你的数据放在哪、安全边界

- `config.json` **只存在于你本机**，权限 `0600`，不会随技能包上传、不会进版本库、不会出现在助手的回复里（展示时自动脱敏）。默认放在技能目录，技能目录不可写时自动改用 `~/.boohee-open-api/config.json`，实际路径以脚本输出为准。
- 助手只记录你**明确说过**的信息，不会从识别结果反推你的身体状况写进档案。
- 随时说「别存我的数据」，助手会清掉该文件并说明清理结果。
- 旧版本遗留的进阶凭证字段会在读取配置时自动丢弃，不会展示或继续使用。

## 文档会过期，技能自带核对能力

官方接口随时会改，`references/` 是某一时刻的官网快照。助手在遇到接口与文档对不上时，会先怀疑文档过期而不是断言接口坏了，并按 `references/07-integration-ops.md`「文档漂移自检与自愈」核对官网当前原文：

```bash
python3 <技能目录>/scripts/fetch_docs.py            # 只读检查，逐篇列出变动
python3 <技能目录>/scripts/fetch_docs.py --apply    # 把官网当前内容写回 references/
```

`<技能目录>` 是本技能安装后 SKILL.md 所在的绝对路径。数据源是文档站的公开接口，无需登录。

## 已知文档不一致

官网文档自身存在若干矛盾（示例域名混用 `api.iboohee.com`、5.1 的 v1/v2 路径、4.3/4.6 下划线与连字符），已在 `references/00-endpoints.md` 末尾逐条列出，调用时以真实返回为准。
