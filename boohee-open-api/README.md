# 薄荷健康食物数据库

一个给 AI 助手用的技能：把**薄荷健康开放接口**（食物营养库、餐食识别、智能食谱、体重与饮食记录）接进你的对话或你自己的应用。

官方接口文档：`https://ai.boohee.com/docs/` ｜ 控制台（拿 API Key）：`https://ai.boohee.com/console/`

技能里的参数表、字段说明、枚举取值、返回示例，全部是官方文档的**逐字快照**，不是二手总结，也不是模型凭记忆写的。助手回答时会说清数据来自哪一级：实时接口返回、官方文档示例，还是模型常识。

## 它能帮你做什么

1. **查食物营养** — 按名称或条码查热量与几十种营养素、GI/GL、红绿灯等级、食材构成、单位估重；多样食物一次算出整餐合计；按营养素做排行。
2. **识别吃了什么** — 拍饭菜照识别食物与重量，或说一句「早上喝了一杯牛奶两个鸡蛋」按餐别拆分。
3. **生成食谱** — 给性别、体重、目标热量，叠加口味、菜系、忌口、慢病与饮食模式（控糖、16:8、高蛋白、素食、地中海、DASH 等），出一整周分餐食谱，支持「换一换」。
4. **记体重与饮食** — 写入、修改、删除、按天查询，返回当日按餐次分组的热量与三大营养素。
5. **帮你写接入代码** — 按官方文档生成 Go / Python / Java / Node.js 调用代码、RSA 签名链路、异步任务轮询、Webhook 验签实现。**这一项不需要 API Key。**

## 怎么开始

在 WorkBuddy 的技能市场安装本技能后即可使用。

- **只想看接口能力与写接入代码**：直接提需求，不需要任何配置。
- **想查真实数据、记录体重饮食**：需要一个 API Key，配一次就长期复用。
  1. 打开控制台 `https://ai.boohee.com/console/` → 登录或注册开放平台账号 → 左侧「API Key 管理」→ 创建 API Key，复制 `sk-` 开头的完整密钥。
  2. 在对话里说「记住我的 key 是 sk-xxx」，助手会写入技能目录下的 `config.json`；也可以自己打开该文件，填最上面带 ★ 的 `api_key` 那一行。
  3. 之后直接说「查一下牛奶按 250ml 算的营养」。

体重、身高、忌口、饮食目标同样说一次即可，助手会记进同一个文件的 `profile` 区块，后续不再反复问。

## 你的数据放在哪、安全边界

- `config.json` **只存在于你本机**，权限 `0600`，不会随技能包上传、不会进版本库、不会出现在助手的回复里（展示时自动脱敏）。
- RSA 私钥只记录**文件路径**，不记录内容。
- 助手只记录你**明确说过**的信息，不会从识别结果反推你的身体状况写进档案。
- 随时说「别存我的数据」，助手会清掉该文件并说明清理结果。
- 没有 API Key 时，助手不会拿模型记忆里的营养数据冒充接口返回；它会改用官方文档示例并明确标注，或者告诉你怎么拿到真实数据。

## 文档会过期，技能自带核对能力

官方接口随时会改，`references/` 是某一时刻的官网快照。助手在遇到接口与文档对不上时，会先怀疑文档过期而不是断言接口坏了，并按 `references/07-integration-ops.md` 第 8 节核对官网当前原文：

```bash
python3 <技能目录>/scripts/fetch_docs.py            # 只读检查，逐篇列出变动
python3 <技能目录>/scripts/fetch_docs.py --apply    # 把官网当前内容写回 references/
```

`<技能目录>` 是本技能安装后 SKILL.md 所在的绝对路径。数据源是文档站的公开接口，无需登录。

## 已知文档不一致

官网文档自身存在若干矛盾（示例域名混用 `api.iboohee.com`、5.1 的 v1/v2 路径、4.3/4.6 下划线与连字符、流式接口路径官方错拼 `image_recongize_stream`），已在 `references/00-endpoints.md` 末尾逐条列出，联调时以真实返回为准。
