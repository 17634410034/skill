# 结果展示规范

取数阶段可以看原始返回；**展示阶段必须重新组织**。最终回复给用户的是「结论 + 易读表格」，不是 JSON、英文字段名或接口原文。

> 下面模板中的食物名与数值仅示意排版，实际回复必须替换成接口返回的真实数据；拿不到就说明失败，不得照抄模板。

## 0. 硬性要求

1. 禁止把 `config.py call` 的输出、接口 JSON、curl 命令整段贴给用户。
2. 第一段先给结论（1-3 句），再给表格与明细。
3. 数值必须带单位；英文枚举翻成中文；缺失写 `—` 并说明原因。
4. 用户没问的字段不抢戏，但接口已取到的完整信息放在「完整信息」小节，不能丢。
5. 一次回复最多 3 个主表格；内容更多时分节，或先给摘要再问是否展开。
6. 不用 emoji；分隔用 `｜`、`→`、`·`。
7. 同一份数据只出现一次，不要在结论和表格里重复罗列。

## 1. 数值与口径

| 项目 | 写法 |
|---|---|
| 热量 | `52 kcal`（整数） |
| 蛋白质 / 脂肪 / 碳水 | `13.5 g`（1 位小数） |
| 维生素 / 矿物质 | 按接口单位，保留 2-3 位有效数字，如 `0.05 mg` |
| NRV | `15%`（接口小数 ×100） |
| 每 100g 口径 | 表头或表下注明；实际摄入按估重/份量折算后另列 |
| 红绿灯 | `绿灯` / `黄灯` / `红灯` / `无等级` |
| GI / GL 等级 | `低` / `中` / `高` / `无数据` |
| 缺失值 | `—`（接口未返回） |

## 2. 食物搜索结果

先回答「哪个更合适 / 热量多少」，再列候选：

```
按热量从低到高，前 5 条如下（营养为每 100g）：

| 食物 | 热量 | 蛋白质 | 脂肪 | 碳水 | 红绿灯 | 常见单位 |
|---|---|---|---|---|---|---|
| 脱脂牛奶 | 33 kcal | 3.4 g | 0.1 g | 5.0 g | 绿灯 | 1 杯 ≈ 250 g |
| ... |

共 32 条，当前展示前 5 条；需要全部或按蛋白质排序可以继续。
```

- 用户要「挑一个」时，最后加一句推荐及理由（热量、蛋白质、红绿灯）。
- 搜索结果较多时先给 10 条以内，并说明总数与 `has_more`。

- 用户只问某一项（如「含糖多少」）时，第一段直接回答，再把完整营养表放在后面。

## 4. 图片识别 / 自然语言识别

先给合计，再按食物或餐别列表：

```
识别到 3 种食物，按估重合计约 520 kcal。

| 食物 | 估重 | 热量 | 蛋白质 | 脂肪 | 碳水 | 红绿灯 |
|---|---|---|---|---|---|---|
| 米饭 | 150 g | 174 kcal | 3.9 g | 0.5 g | 38.6 g | 黄灯 |
| 番茄炒蛋 | 200 g | 170 kcal | 9.0 g | 12.4 g | 7.6 g | 绿灯 |
| ... | | | | | | |

合计：520 kcal ｜ 蛋白质 28 g ｜ 脂肪 25 g ｜ 碳水 62 g
```

- 识别结果必须按 `amount` 折算成实际摄入，不能直接报每 100g。
- 有 NRV 时在合计后补一行主要营养素 NRV；用户关心控糖/控压时优先展示糖、钠、GI/GL。
- 自然语言识别按 `time_type` 分节：早餐 / 中餐 / 晚餐 / 早加餐 / 午加餐 / 晚加餐。

| 候选 | 份量 | 热量 | 蛋白质 | 脂肪 | 碳水 | 红绿灯 |

## 7. 体重与体脂

先给趋势结论，再列记录：

```
最新：64.3 kg（2026-05-11 08:00），体脂 22.5%。
近 30 天：下降 1.2 kg（65.5 → 64.3），最低 64.3 kg（05-11），最高 65.8 kg（04-15）。

| 日期 | 体重 | 体脂 | 测量时间 |
|---|---|---|---|
| 2026-05-11 | 64.3 kg | 22.5% | 08:00 |
| ... | | | |
```

- 记录少于 2 条时不做趋势判断，只报最新值。
- 曲线接口返回的是点序列；用「起点 → 终点、变化量、最高/最低」概括，不贴坐标数组。

## 9. 错误、空结果与异步未完成

- **空结果**：`没查到「xxx」。可以换一个更通用的关键词，或确认条码是 13 位。` 不贴空 JSON。
- **参数错误**：用一句中文说明原因与修法，例如 `关键词超过 30 字，被接口拒绝；我截短后再查一次。`
- **凭证错误**：`当前 API Key 不可用（接口返回 1049），需要重新配置。` 然后走 SKILL.md 的凭证流程。
- **异步处理中**：`识别还在处理中（status=1），通常需要几秒；我稍后再查一次。` 不要把中间状态当结果。
- **识别失败/未识别**：说明 `status=3`（没识别到食物）或 `status=4`（识别失败），有 `err_message` 时翻译成人话。
- **翻页**：`以下为第 1 页 20 条，共 135 条；需要继续翻页告诉我。`
