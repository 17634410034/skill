# 薄荷健康

让 AI 助手直接调用薄荷健康的食物库与健康数据能力，把「查营养、识别餐食、配食谱、记体重、记饮食」接进你的应用或对话流程里。所有数据都来自官方开放接口（`https://api.boohee.com/open-apis`），不是模型凭记忆编的。

## 能做什么

### 1. 查询食物与营养成分

- 按名称或商品条码查热量、蛋白质/脂肪/碳水等几十种营养素
- 拿到 GI/GL 升糖指数、红绿灯健康等级、食材构成与可食部
- 按分类浏览食物，查「一碗米饭」这类日常单位与估重
- 多样食物一次算出整餐合计营养
- 按营养素做排行，快速挑高蛋白 / 低脂 / 低嘌呤的选择

### 2. 识别你吃了什么

- 拍一张饭菜照，识别出食物并给出重量、热量与营养素占比
- 说一句「早上喝了一杯牛奶、吃了两个鸡蛋」，按早/中/晚餐与加餐拆分并匹配食物库条目
- 支持异步查询与流式边识别边出结果，适合做「拍照记录饮食」

### 3. 生成个性化食谱

- 输入性别、当前体重、目标热量即可开始
- 可叠加口味偏好、菜系地区、减重/增肌目标、忌口、慢病与饮食模式（控糖、碳水循环、16:8、高蛋白、素食、地中海、DASH 等）
- 生成一整周分餐食谱，可对某餐的一道菜「换一换」，替换单菜或整餐
- 附带食谱概要与饮食模式科普（介绍、禁忌人群、FAQ）

### 4. 记录和查询体重、体脂

- 写入体重与体脂，删除误记
- 按日期区间取历史，或取某日前最新一条
- 直接拿体重 / 体脂曲线数据做趋势展示

### 5. 记录和查询饮食

- 按餐别批量或单条写入，支持删除与修改（分量、单位、餐别、时间、热量）
- 查某天全部记录与当日最新
- 每次写入都返回按餐次分组的当日总热量、蛋白、脂肪、碳水

### 6. 完整接入支持

- 两种认证方式，异步任务与 Webhook 事件回调对接规范
- Go / Python / Java / Node.js 官方 SDK 指引
- 错误码排错、枚举速查、常见坑与官方文档过期自愈

## 怎么用起来（三步）

**第 1 步：拿一个 API Key**

打开控制台 `https://ai.boohee.com/console/` → 登录开放平台账号（没有账号就在控制台注册）→ 左侧「API Key 管理」→ 创建 API Key → 复制以 `sk-` 开头的完整密钥。

**第 2 步：把 key 填进去（只需要这一个）**

打开技能目录下的 `config.json`，最顶上带 ★ 的必填区块里就有 `api_key` 那一行，把占位文字替换成你的密钥即可，其他区块先都不用动。

如果还没看到这个文件，跟助手说一声「帮我初始化配置」，它会生成好。

不想手动编辑文件也可以：直接在对话里把 key 告诉助手，说「记住我的 key 是 sk-xxx」，助手会帮你填好。

**第 3 步：直接提需求**

- 「查一下牛奶按 250ml 算的营养」
- 「拍这张饭菜照，看看我吃了什么」
- 「帮我排这周三餐，我要控糖」
- 「记录我今天早餐吃了全麦面包两片」

之后的身体数据也不用你操心：说一声「我体重 62kg」「我是女生」「我不吃香菜」「我的 user_id 是 U1001」，助手会自动记进同一个文件的 `profile` 区块，后续调用直接复用，不再反复问你。

> `config.json` 只留在你本机（权限 `0600`，已被 `.gitignore` 排除），不会提交到仓库、也不会随技能包上传。随时可以说「别存我的数据」让助手清掉。

## 必须遵守的规则

1. **先查本地配置，再问用户**：调接口前先 `python3 scripts/config.py show`，已有可用 key 就直接用。`api_key` 还是占位文案或含中文时等同没填，不要拿它发请求。
2. **禁止凭记忆编造**：所有参数、字段、枚举一律查 `references/`；未文档化的字段/接口先向用户确认。
3. **对不上先怀疑文档过期**：按操作细则的「文档漂移自检与自愈」核对官网原文，不要断言接口坏了，更不要改文档去迎合实现。
4. **不得用模型记忆的数据冒充接口返回**：用户确实没有凭证、又只要参考值时，必须在开头标注「非薄荷食物库返回，`food_code` 不可用于写入」。
5. **凭证与个人数据**：不回显完整值、不写进代码、不进提交、不上传；RSA 私钥只记文件路径，不记内容。
